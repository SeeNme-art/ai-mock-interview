AI 模拟面试系统
一个「敢上线」的面试 Agent

面向技术岗求职者：选定岗位、粘贴简历，系统按六阶段完成一场完整面试——逐题提问、针对回答追问、 按 rubric 打分、输出可执行的改进报告。它同时是一个工程样板：每一次模型调用、每一次检索、每一次语音合成 都被记录、可回放、可度量。

一句话定位：流程由确定性状态机控制，模型只在节点内完成「出题、追问、评分」三件事。

01 / 用户旅程

一个人从打开页面到拿到报告，只经过六个环节

主线操作只有两种：填 和 确认。除此之外系统自己跑。

1
配置面试用户
填岗位名称、级别、题数；粘贴 JD 与简历；可选上传面经逐字稿。三类资料会被统一建库。
2
构建知识库系统
解析 → 脱敏 → 按问答成对切分 → 向量化入库。全流程 3 秒左右，页面展示每一步的进度与结果（如「42 个片段」）。
3
确认大纲用户
看到考察维度与题目清单，可换题、调难度。这是用户唯一能干预出题的地方，也是 RAG 召回结果的可视化窗口。
4
语音提问系统
文字先流式逐字出现，同时按句送进 TTS。首字可听控制在 1.2 秒内，句中不停顿，可被用户打断。
5
作答与追问用户
语音或打字作答。只有当回答少于 80 字、或没命中考察要点时才追问，单题最多 2 轮。
6
面试报告系统
总分、四维雷达、逐题明细（含参考答案要点）、短板 TOP2 与学习路径，可导出 Markdown。
02 / 分层架构

四层业务 + 一层旁挂

所有能力模块都是被状态机调用的「哑模块」——它们不知道自己当前是第几题、下一步该干什么。

为什么旁挂：观测与评测一旦写进业务流程，就会变成「为了指标好看而改业务」。 旁挂保证它们只能读、不能改，业务逻辑永远只由状态机决定。

04 / 知识库

三类输入，两条通道

建库是离线的一次性动作，检索是每道题都要跑的实时动作。两者用 FAISS 解耦。

关键取舍：JD 与简历不做检索，直接全量注入 Prompt。它们只有一两千字，检索一旦漏召回， Agent 就完全不知道你简历写了什么——追问会当场崩掉。向量库只负责跨场复用的公共语料。

05 / 工程护甲

四层护栏，让 Agent 敢上线

企业从不直接信任模型。企业信任的是：规则 + 限制 + 兜底。

1
模型调用限流
单题最多 4 次模型调用。防的不是答得不好，是停不下来。
2
工具调用限流
检索工具单题 3 次。防止成本失控与被下游封号。
3
隐私脱敏
手机号、邮箱、身份证在入库前自动打码。模型可以犯错，系统不能违法。
4
人工确认
导出报告、发送邮件前必须人工 approve / edit / reject。AI 不对关键行为负最终责任。

触发后的动作同样重要：限流不是直接抛异常，而是优雅收尾——保存已完成的题目、生成阶段性报告、 在 trace 里标记 guard.limit.hit，用户看到的是「本场面试已结束」，不是报错页。

07 / 自评测

把「感觉还行」变成一条曲线

30 条手标样本，六个指标，每次改动自动与上次基线对比。

指标是互相制约的：chunk 越大，召回率升、精度降、成本涨。所以调优不是把某个指标拉满， 而是在「每场 ≤ 3 万 token」的约束下最大化 Recall@3。每改一次参数记一条实验记录，八组之后 手上就有一条完整的决策链。

09 / 一句话概括
如果面试官只给你 30 秒介绍这个项目，这么说：
这是一个 AI 模拟面试系统，用 LangChain v1 + DeepSeek 实现。核心设计是流程与智能分离—— 六阶段面试由一个确定性状态机编排，模型只在节点内完成出题、追问、评分三类任务，避免 Agent 自主决策带来的不可控。 知识库把 JD、简历、面经统一建索引，出题和评分都基于召回结果，做到有据可依、可追溯。 工程侧加了四层护栏（限流、工具限制、脱敏、人工确认）、自建的链路观测平台， 以及一套带基线门禁的评测体系——每次改 Prompt 都能看到召回率和延迟是涨了还是跌了。
