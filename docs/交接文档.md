## 1. 项目定位（一句话）

**一个能追问的面试官，不是刷题工具。**

区别在于：普通题库 App 问「RAG 的召回怎么优化」，答完给分，结束。
这个系统会接着问「你刚才说换了 pgvector，那多租户过滤你是怎么做的？」——**追问基于你的简历和上一句回答**。

所以「个性化」（简历驱动的改写题/生成题）和「可追问」（最多 2 轮）是它的核心，**不是可选项**。任何简化都不该砍掉这两点。

## 3. 不要推翻的决策（附理由）

> 这一节是本文档最重要的部分。以下每一个结论都是**讨论过、推翻过、最终定下来的**，理由写在这里，避免重新走一遍弯路。

### 3.1 架构

| 决策 | 结论 | 关键理由 |
|---|---|---|
| **编排** | LangGraph 做编排 + LangChain 做节点内能力，**不引 LlamaIndex** | `create_agent` 内部就是 LangGraph，不是二选一 |
| **状态机** | **纯 Python `TRANSITIONS` dict + `fire()`**，P2.5 才平移 LangGraph | 先跑通流程再叠框架，否则两个问题一起卡 |
| **模型不判定流程** | 状态迁移条件 100% 由代码判断（字数/轮次/命中要点） | 模型判错会导致会话卡死；质量判定（如改写是否可用）例外，规则见 5.6.3 |
| **追问上限** | 最多 2 轮，由 `probe_count` 硬卡 | Prompt 里不写轮次规则——那样会有两处实现，且模型不可靠 |

### 3.2 前端（v1.5.2 定的，改过一次）

| 决策 | 结论 | 关键理由 |
|---|---|---|
| **MPA 不是 SPA** | 5 个 Jinja2 模板页 | 四/五个界面之间只传 `session_id`，**几乎零共享状态**；SPA 的价值用不上，而它的经典坑（切视图忘解绑 → 重复触发）是真的风险 |
| **不引入构建工具** | 无 npm / vite / webpack | 它只解决「源码打包」，本项目没这问题 |
| **允许第三方库** | 放 `static/vendor/` | ⚠️ v1.5.2 曾写「什么都不装」是**错的**，已修正为三层（构建工具/库/框架） |
| **不用 React** | Jinja2 + 原生 JS | 作者**只会 Flask**，而 Flask 默认模板引擎就是 Jinja2，模板部分零成本 |

> **不要重新提议上 React**。除非满足 2.5.5 的五条判据之一（页面>10 / JS>5000 行 / 多人协作 / 移动端 / 复杂跨视图状态）——目前一条都不满足。

### 3.3 数据

| 决策 | 结论 | 关键理由 |
|---|---|---|
| **简历不存原文** | 白名单字段 + `raw_excerpt`（项目段落摘录） | 从黑名单脱敏改为白名单提取，**漏检在结构上不存在** |
| **JD 存全文** | 只过滤联系方式行 | JD 不是 PII 密集的，正文是出题的关键上下文 |
| **删除是硬删** | 无 `deleted_at` | 软删有欺骗性（以为删了文件还在），且边界太多 |
| **删除顺序** | **先删文件，后删库** | 反过来文件删失败时数据库已提交无法回滚，**留孤儿行（有害）**；孤儿文件无害 |
| **外键** | `PRAGMA foreign_keys=ON`，但**不用 CASCADE** | SQLite 默认关闭外键，`REFERENCES` 只是注释；但 10 张表一起级联，出事了不知道删了什么 |
| **评分双轨** | 知识题 4 维要点比对 / 项目题 STAR 4 维 | 用一套评分器评两类题是错的（5.8.1） |

## 5. 已知的坑（血泪教训）

### 5.1 编辑设计文档时

**这个错误在本次会话中犯了 6 次**：

> 在 Markdown 代码块的**中间**插入引用块（`>` 或表格）后，**忘记重新打开 ` ``` `**，导致后续的 `CREATE TABLE` 掉到代码块外，全文渲染错乱。

**规则**：任何一次在代码块附近插入内容之后，**立刻**跑这段检查，不要攒到最后：

```bash
python -c "
s=open('docs/设计文档.md',encoding='utf-8').read()
L=s.split(chr(10)); F=chr(96)*3
inb=False; o=c=0
for l in L:
    if l.startswith(F):
        if not inb: o+=1
        else: c+=1
        inb=not inb
print('fences', o, c, '->', 'OK' if not inb and o==c else 'BROKEN')
"
```

**为什么「攒到最后」会失效**：围栏总数变奇数时，`inb` 状态全程反转，「块外代码检查」会**误报「无」**。必须先确认围栏是偶数对，块外检查才有意义。

### 5.2 代码里的坑（文档已记录，实现时别忘）

| 坑 | 正确做法 | 出处 |
|---|---|---|
| `SequenceMatcher.ratio()` 比对长原文 | 用「最长公共片段 / len(a)」 | 5.9.5 |
| 裸用 `IndexFlatIP` | 用 `IndexIDMap2` 包一层，否则重建后 `faiss_id` 全错位 | 5.4.2 |
| 裸用 `IndexFlatIP.search()` 的返回值当 chunk_id | 它是**数组行号** | 5.4.2 |
| 分句算法无标点时不切 | 必须加 `MAX_LEN=30` 兜底，否则音频一句不播且**无报错** | 6.2 |
| `run_limit` 设成正常调用次数 | 要留重试余量（4→6） | 3.5 |
| SQLite 外键默认关闭 | 每个连接执行 `PRAGMA foreign_keys=ON` | 7 章 |
| 删除时先删库后删文件 | 反过来会留孤儿行 | 7.3.2 |

### 5.3 概念陷阱

| 易混 | 区别 |
|---|---|
| **React vs ReAct** | React = 前端 UI 库；ReAct = **Re**asoning + **Act**ing，Agent 推理范式。**毫无关系** |
| **Jinja2 vs SPA/MPA** | 不是同一维度。SPA/MPA 回答「几个页面」，Jinja2 回答「HTML 在哪生成」 |
| **暂停 vs 中止** | 关页面 = 暂停（可续，靠 `/state`）；点「结束面试」= 中止（不可续，出部分报告） |
| **部分报告 vs 完整报告** | 靠 `report.is_partial` 区分，**必须在横幅写「已答 X/Y 题」**，否则用户会横向比较 |

## 9. 一句话建议

**这份文档最大的价值不是「写全了」，而是「每个结论都有理由」。**

接手时如果觉得某处设计别扭，先去 17 章的变更记录里找对应的条目——**大概率是因为某个坑才变成这样的**。如果确实要改，改完记得同步更新变更记录，并说明新理由。

反面教材：本次会话中发现 **2 处「注释描述了一个不存在的行为」**（`ABORT` 声称会中止但会抛异常、`ABORTED` 声称已产出报告但没人生成）。**写下来的承诺，代码里必须有执行者。**
