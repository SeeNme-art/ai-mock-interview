# 05 · 评测与交付计划

> v2.0 · 依据 D21–D24。本文规定未来验收方法；没有把待做评测写成已通过结果。
> 当前实现状态见[交接文档](记录/交接文档.md)，实验原始记录见[实验记录](记录/实验记录.md)。

## 1. 测试与模型评测的分工

| 层次 | 检查什么 | 是否付费调用 |
|---|---|---|
| 单元与组件 | 状态规则、计数、聚合、字段出处、预算预留、版本校验 | 否，纯函数或 fake |
| 集成与故障注入 | 接口、幂等、落库、恢复、删除、报告降级 | 否，可注入 fake 模型、临时库与文件 |
| 材料解析 | 文本型 PDF/DOCX 和不支持扫描件的提示 | 默认否，合成文件随测试提交 |
| 检索评测 | 实际 query 构造、合格候选排序、Hit/Recall/MRR | 本地 embedding 为主，若换收费服务需记录 |
| 生成与评分评测 | 个性化、追问价值、评分证据与人工判断 | 按需手动真实调用，先确定试测费用上限 |
| 产品验收 | 浏览器完整流程、异常体验、反馈可理解性 | fake 与少量真实样本分别标识 |

CI 默认不访问真实模型、不依赖开发者密钥。模型客户端可注入，重试与预算不能在 fake 路径被完全跳过。已通过检查只有在变更影响或发现风险时重跑，不无目的重复付费评测。

## 2. 小规模评测数据

| 数据 | 首版规模目标 | 内容与标注 |
|---|---|---|
| 核心问答场景 | 约 20 组，调试/保留各约 10 | 自带材料、正式问题、回答、追问历史、适用维度、人工可接受结果；知识/项目均覆盖 |
| 检索查询 | 约 30 条 | 自带 JD/技能/当前考察点与约束，人工标注相关 question IDs；走与产品相同的 query 构造 |
| 材料输入 | 约 10 份支持格式样本 | 文本、单栏/双栏文本 PDF、DOCX；标出应提字段、项目归属、关键数字 |
| 明确不支持输入 | 少量独立负例 | 扫描件、损坏文件、超限输入；验证提示与回退，不计入支持格式提取成功率 |

所有样本带 ID、版本、来源/合成说明和 split。近义改写、同一项目的衍生样本放同一 split，避免调试集与保留集实际重复。不得把题库生成时填写的 source_refs 直接当完整相关性金标准；同样相关的其他题应人工补标。

核心案例至少覆盖：短而正确、长而空洞、技术错误、合理替代答案、答非所问、无量化结果但有验证方法、个人贡献不清、前后矛盾、明确不会、提示注入、无项目、材料不相关，以及最多两轮追问后收尾。

允许同一案例分别检查生成、追问、评分、报告，以减少标注量；不同能力使用各自适用分母，不把所有案例都塞入一个“总准确率”。作者依据资料人工核对并记录不确定性，不能将个人标注称为招聘专家共识。

## 3. 必须通过的确定性用例

| 用例 ID | 场景 | 必须成立的结果 |
|---|---|---|
| C01 | 提交成功后响应丢失，同 key 重发 | 只有一份答案和同一个 operation |
| C02 | 同 key 改正文 / 新 key 重复同轮 / 旧标签页提交 | 拒绝冲突，不覆盖、不重复推进 |
| C03 | 生成中刷新、完成后刷新 | 不接收无正式题目的答案；完成后展示同一正式问题 |
| C04 | 用户关闭页面 | 已接受操作只到下一等待边界，不自动替用户作答 |
| C05 | 答案已落库后进程退出 | 重启显示待恢复，用户继续后不会丢答案 |
| C06 | 评分已写、图 checkpoint 尚未写时退出 | 恢复复用评分，不重复计分与报告修订 |
| C07 | 已展示两轮追问 | 不再调用追问模型，也不出现 round_no=3 |
| C08 | 四题回答、一题跳过；全部跳过 | 正常收尾；跳过不记零；无有效分只显示摘要 |
| C09 | 模型调用期间中止，旧响应迟到 | 会话不被重新激活；允许的 finalize 独立运行 |
| C10 | 评分/报告服务失败 | 评分待补评；报告模板或摘要；没有固定假分 |
| C11 | 有回答时中止、零回答时中止、重复中止 | 已提交内容保留；报告失败也已结束；幂等 |
| C12 | 硬预算不足、SDK/图重试、用量未知 | 不超应用允许范围继续调用；未知不当零，次数不被重置 |
| C13 | 删除时文件已缺失、某步失败、重启、迟到 trace | 能继续清理，成功前不声称完成，删除后不重新写入副本 |
| C14 | 应用内备份含已删除会话 | 备份清理/恢复检查生效，不复活用户数据 |
| C15 | 数据迁移失败、版本不兼容 | 停止并提示，不清空用户库；旧备份/迁移有记录 |
| C16 | 空提取、数字改变、跨项目串字段、字段遗漏 | 空值不判 exact；风险有提示；评测分母计遗漏 |
| C17 | N/A、评分失败、模型算错总分、伪造引用 | 代码正确聚合；失败无能力分；伪造结果不被接受 |
| C18 | 索引版本不符或没有合格审核候选 | 不用错版本或未审核题，明确降级/提示 |
| C19 | 默认真实材料执行 | 日志、trace、checkpoint 和异常中没有正文副本 |
| C20 | 恶意 HTML、路径、Prompt 指令 | 页面不执行不可信 HTML，不越界访问文件，不绕过动作与评分契约 |

这些是具体契约测试，不以“覆盖率达到 80%”代替。至少覆盖主要正常路径及每个核心失败分支。测试不承诺证明模型从此不会犯错，内容质量还需下面的评测。

## 4. 内容质量与指标

| 能力 | 指标与人工检查 | 不应混淆的事情 |
|---|---|---|
| 个性化出题 | 引用项目事实正确、问题相关、考察点不漂移；报告通过数/适用数 | 插入技能名称不等于有效个性化 |
| 追问 | 是否针对本次回答、是否增加信息、是否重复或泄露答案 | 追问次数多不等于质量好 |
| 检索 | Hit@3、Recall@3、MRR、无合格候选率；按方向分组 | 没有候选和索引故障不是同一类错误 |
| 评分校准 | 是否落人工可接受区间、维度判断、好/差答案排序、技术疑点是否有依据 | 格式合法或低温不等于正确 |
| 评分稳定性 | 选一小组固定答案重复 3 次，报告每题波动与版本 | 小样本波动不推导整个人群信度 |
| 报告 | 建议能否定位到回答、能否执行、是否编造结论 | 文笔顺畅不是有效反馈 |
| 提取 | 应提字段覆盖率、准确出处、关键数字/归属错误、人工修正数量 | exact 率不能掩盖漏提 |
| 时延 | 准备请求到正式题面可见、提交到下一可用交互；P50/P95、样本数、冷热启动分开 | 首 token 不代表用户已收到有效问题 |
| 成本 | 每场、每环节、重试、失败、预览与评测总量；估计/实际分开 | 40000 token 不是固定金额 |

检索公式：Hit@K 为至少命中一个人工相关候选的比例；Recall@K 为命中相关候选数/全部标注相关候选数后按查询平均；MRR 未命中取 0。G 为空的负例单独计算正确拒绝/覆盖提示率，不制造除零。实际不足 K 时同时报告候选数，不把有效过滤误算成模型错误。

## 5. 门槛、冻结与基线

1. 先用调试集建立可理解的标注规则和初步结果；记录哪些失败属于设计、实现、材料或模型。
2. 将各指标的绝对下限、允许波动、人工否决项、样本版本和计算程序冻结为一个验收配置，关联 commit/hash。
3. 在没有利用保留集调 Prompt 的条件下运行验收；保留集一旦用于修改模型策略，就不再宣称它是未见验收集，应补新保留样本。
4. 未通过时修正或明确缩小已支持范围，重新说明版本与样本变化，不能只反复降低阈值。
5. 发布基线保留不动。候选结果只新增记录；升级基线需要写出理由和对比，不自动用每次略差的通过结果覆盖旧值。

当前不填未经验证的 Recall、MAE、P95 数字。**必须在首版模型质量验收前完成阈值冻结**，否则只能称流程演示可用，不能称产品质量已验收。任何评测集上发现伪造用户经历/引用或系统故障假分，都需作为具体阻塞问题处理，不能被平均值隐藏。

## 6. 里程碑与交付物

新里程碑用 M0–M5，旧交接中的 P0–P7 仅指历史计划；M0 不是假定旧骨架全部正确。

| 阶段 | 实现与验证成果 | 作者应能解释 | 出口条件 |
|---|---|---|---|
| M0 现状与小实验 | 复核 P0 实际运行位置与观测隐私差异，锁定可用依赖；最小 LangGraph 暂停/恢复；模型结构化与预算试测 | 图与业务库为何不同、哪里可能重放 | 有运行证据与可复现说明；真实调用前费用上限确定 |
| M1 最小数据与内容 | 约 10 道审核题、题库检索、已确认画像、迁移与版本快照 | 内容从哪来、怎么确认正确、索引为何可重建 | 纯文本材料可保存，候选可解释，迁移/聚合测试通过 |
| M2 CLI 完整闭环 | 5 题混合/知识专项，追问、分类评分、报告、中止、恢复、预算 | 一次回答从接收到报告经历哪些写入 | 正常与关键失败路径跑通；第一次端到端演示形成 |
| M3 本地浏览器闭环 | 五个页面、示例/文本入口、状态查询、历史/继续/删除/导出 | 页面进度为什么以服务端为准 | 用户不用 CLI 能面完；刷新和重复提交可验证 |
| M4 补齐首版 | PDF/DOCX、约 30 道审核题、约 20/30/10 评测样本、输入上限和错误提示 | 哪些解析/评分失败可接受、怎么测 | 支持范围与文档一致；5/8 题配置边界有验证 |
| M5 验收与证据 | 固定基线回归、演示、运行说明、实验结果、交接 | 能解释效果、代价、失败与后续路线 | 硬门禁与冻结质量门槛通过，缺陷明确，无伪造结果 |

测试、数据最小化、预算和观测随模块建设，不延期到最后“加护甲”。每阶段写开发日志和理解检查；模型/检索修改写实验记录；真实故障写问题记录。

按每天约 4 小时含理解代码安排任务，不用固定天数掩盖学习成本。M2 完成后依据实际工时重新估计剩余工作。如果某阶段停滞，缩小实验问题、记录阻塞与下一项可验证动作，不无限打磨文档。

首版证据包：可运行项目/依赖与启动说明、约 5 分钟演示、至少一次受控方案对比、故障恢复案例、真实问题索引、项目讲解提纲。结果可以无提升或退化，但必须说明据此保留/放弃了什么。Docker 可作为复现附加项，不能取代明确的本地运行说明，也不是当前业务闭环的前置条件。

## 8. 面试证据与记录纪律

每个可讲的案例尽量形成链条：用户/工程问题 → 当时假设 → 实际排查 → 方案取舍 → 验证结果 → 限制。引用代码路径、测试名、实验 ID、脱敏输出或提交号。

设计讨论可讲为“为什么这样设计”；只有真实发生并有证据的排查才能讲为“我遇到并解决过”。假模型测试叫故障注入，不能描述为真实生产事故。没有部署上线时不写“线上高并发稳定运行”。

日志可以记录“功能已做，但我还不能独立解释恢复流程”，理解状态无需伪装为全部掌握。具体模板在记录目录，首版交付时从真实记录整理讲解提纲，不预先编故事。
