# M2 第三批 · 首答保存与同轮防重

日期 2026-11-21，开发基线 `474fa17`。本批让用户提交第一条回答，并能在新终端核对保存进度。

## 提交后发生什么

1. `answer` 接收 UTF-8 文本、会话 ID、题目 ID、轮次 ID、当前 `revision` 和请求标识。服务检查会话归属、当前已展示轮次及可提交状态。空白回答被退回，“不知道”可以保存。命令行的初始上限为 8,000 字符，统一换行并保留缩进。
2. 在一笔事务内把文本写入原有 `exchange`、记录 UTC 时间、更新进度并创建一个 `queued` 操作。事务提交后返回 `accepted=true`。换一个请求标识也无法再次写入这轮答案。
3. 同键同内容返回原接收回执，`state` 查看当前保存进度。显式读取可以看见自己的题面和答案。任务与接收回执不保存正文副本。CLI 当前以 `processing` 和 `queued` 表示等后续处理。

## 验收结果

| 检查项 | 实际结果 |
|---|---|
| 提交与重读 | 实跑题库导入、材料确认、计划、开始、首答和新进程读取。保存后的 `revision` 为 5，回读内容与合成答复一致 |
| 重复与覆盖 | 相同命令得到原回执。同键改正文冲突，旧修订和已答轮次均不能覆盖原答案 |
| 并发 | 两条相同请求只登记一条操作。两条不同请求同时抢同一轮，只接受先写入的一条 |
| 回滚 | 注入任务插入失败后，答案、题目状态、修订和控制代次都回到事务前。故障解除后原键可重试 |
| 输入与范围 | 合成样本覆盖 8,000 字符边界、中文与缩进、非法 UTF-8、全空白、错会话、旧轮次与删除中的会话 |
| 正文边界 | 操作字段与接收回执的合成正文标记检查通过，正常答案保存在业务表 |
| 全量回归 | 新增 12 项、最终全量 94 项通过。首轮临时观测库被占用，单独复跑三次通过，见 [ISSUE-006](问题记录.md#issue-006--p0-http-回归偶发无法清理临时观测库) |

本批复用数据库 v3，模型调用 0 次。已登记的操作将在下一阶段由回答处理节点消费。

## 怎样复现

先按[首题准备](阶段审阅-M2首题准备.md#怎样复现)完成合成会话并拿到正式题。以下命令沿用对应的 `$py`、`$demo` 和 `$session`。

```powershell
$state = & $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session | ConvertFrom-Json
$file = "$demo/synthetic-answer.txt"
Set-Content -LiteralPath $file -Encoding utf8 '工作流预先规定步骤，Agent 可以在权限范围内选择下一步。'
$submit = @('answer', $session, $state.current.turn_id, $state.current.exchange_id,
            '--expected-revision', $state.revision, '--key', 'demo-answer', '--answer-file', $file)
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" @submit
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" @submit
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session
& $py -X utf8 -m unittest discover -s tests -p 'test_answers.py' -v
```

两次相同的 `answer` 会输出同一个接收回执，随后 `state` 展示已保存的答案和排队操作。
