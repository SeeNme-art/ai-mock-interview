### EXP-003 · 筛选后的同一批题怎样排序

- 对应 X06 / D17 / DEV-20261121-02。代码基线 `9ae5b03` 加本批工作区，10 道题均为修订 2。真实模型使用 Qdrant 发布的 ONNX 快照 `46fbe35`，CPU 向量维度 512。查询构造为 `objective-jd-skills-v1`。具体依赖版本、题目哈希和向量文件哈希见[原始结果](实验产物/EXP-003-retrieval-synthetic-debug-v1.json)。
- 先写 6 组考察点、相关 JD、技能与目标题，每个方向两组。两条路径使用同一 SQLite 过滤结果，每组有 2–3 道合格题。基线按稳定 ID 排序，实验只改变排序。逐样本记录目标题、两种顺序与向量分数。
- 首位命中从固定顺序的 2/6 到向量排序的 6/6。向量前三命中 6/6，每组候选最多三题，仍需更多题来判断 Top 3 覆盖。搜索与重建均用真实本地模型，运行时拦截 Python socket 连接。付费调用 0 次。
- 在新装的隔离环境中从独立空库重跑，索引 SHA-256 和全部六组排序、分数小数点后六位一致。该[原始 JSON](实验产物/EXP-003-retrieval-synthetic-debug-v1.json)的 SHA-256 为 `28a90017f1b7e2c2751112e8cb0e436a3123e0a65ac2fd56b2cb83c0d7d0f86b`。
- 本轮样本面向已有题手工编写，未覆盖歧义、跨主题 JD 和完整会话。Top K、模型选择、分数阈值与端到端效果仍待扩充题库后验证。当前没有启用相似度阈值，也没有用相似度作为面试评分。

### EXP-001 · checkpoint 不代替业务写入幂等

- 关联：X02、D13、DEV-20261119-04；代码基线 a420cfa，实验脚本新增于工作区。
- 已测脚本 SHA-256：`E0A65933BC3356F8C63D975C35D615E825057F59ACBFDDDD60A8225FE09E3D86`。
- 原始 JSON SHA-256：`A51D2D8AF92CD5FF70FF5C69733C932601E87BEFF444D9041EB82B3DCB8A1A59`，与运行目录产物一致复制，未改写数字。
- 样本：一个合成操作、一个固定步骤；同一图结构，主变量为是否启用 completed_steps 唯一键和原子结果复用。每个命令使用独立进程，首轮完整运行一次，非性能基准。
- 结果：直接写入暂停恢复后 visits=2/effects=2；去重版 visits=2/effects=1；硬退出 73 后恢复 visits=2/effects=1；新 graph 代次重建后 visits=3/effects=1。
- 负例：两种策略均用错误 thread_id 发起恢复，由实验入口检查待执行状态后拒绝，未增加业务记录；这不是框架自动完成了业务鉴权。
- 材料只在 business.db；图 state / interrupt / resume / 返回结果只传引用和计数，检查解码 checkpoint、pending writes、数据库列与进程输出均未发现合成正文标记。
- 执行与范围：独立 .venv-langgraph 安装必要框架和 SQLite saver，41 个实际版本冻结；pip check 通过。未使用 P0 虚拟环境、模型或真实材料。LangSmith tracing 显式关闭，子进程 socket.connect 被拦截；这不是 OS 防火墙隔离。
- 决定：采用业务库结果去重作为正式实现依据；仍需后续实现操作权限、epoch、取消、预算和旧代次清理。
- 限制：本地 SQLite 副作用可与步骤结果同事务，远程模型/工具请求不具备此条件；本实验不证明远程 exactly-once、零重复计费或全部故障都可恢复。未做并发压测、模型试测或生产迁移。

## 3. 证据保存规则

- 原始结果使用机器可读 JSON/JSONL，Markdown 只写摘要和解释；命名带实验 ID 与数据版本。
- 公开仓库只提交合成/可分享样本与去敏结果；真实用户材料不作为默认实验集。
- 保留完整分母和失败样本，不能只截成功例子；结果退化同样记录。
- 未实际运行的数字只能标估算；旧设计中的示例数值不能迁移为本项目测量结果。
- 不自动覆盖发布基线；若修改，记录旧/新版本和明确理由。
- 每次付费运行先确定调用规模与费用上限，停止条件由代码执行；日志没有 usage 时标未知，不写零。
