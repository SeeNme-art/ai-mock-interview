## 2. 实验模板

```markdown
## EXP-NNN · 本次想验证的假设
- 日期 / 执行者 / 关联需求与开发日志：
- 为什么做：来源于哪个失败样本或成本问题
- 基线：代码/Prompt/rubric/题库/索引/模型版本及参数
- 候选：本次改变的一个主要变量；无法单变量时如实记录
- 样本：数据集版本、split、数量、排除规则
- 人工标注：判据、核对者、不确定或争议项
- 执行：具体命令、随机性控制、重复次数、环境
- 预算：批准或明确配置的上限、估计值、实际 usage 与金额、未知用量
- 结果：逐样本原始产物路径、指标、失败样本、耗时与样本数
- 决定：保留 / 放弃 / 继续验证；理由与代价
- 限制：是否只在调试集成立、是否存在小样本或供应商漂移
- 后续：需要修改的设计、代码、测试或交接
```

## 3. 证据保存规则

- 原始结果使用机器可读 JSON/JSONL，Markdown 只写摘要和解释；命名带实验 ID 与数据版本。
- 公开仓库只提交合成/可分享样本与去敏结果；真实用户材料不作为默认实验集。
- 保留完整分母和失败样本，不能只截成功例子；结果退化同样记录。
- 未实际运行的数字只能标估算；旧设计中的示例数值不能迁移为本项目测量结果。
- 不自动覆盖发布基线；若修改，记录旧/新版本和明确理由。
- 每次付费运行先确定调用规模与费用上限，停止条件由代码执行；日志没有 usage 时标未知，不写零。

## 4. 首次方案对比的建议（计划，未执行）

可比较同一模型、同一材料与同一调试集上，“固定追问提纲”与“结合本题问答历史的动态追问”。人工检查关联性、重复、信息增量和答案泄露，同时记录调用成本与等待时间。结果若没有提升，应保留失败样本并调整方案，而不是预设动态方案必胜。
