日期 2026-11-21，开发基线 `c500155`。本批交付开始面试、保存首道正式知识题及其评分依据、按会话 ID 读取进度。

## 从计划到首道正式题

1. `start` 校验会话的阶段、当前 `revision` 和请求标识。在一个事务内锁定计划版本、把会话置为 `ACTIVE`、增加控制代次并登记 `queued` 开始操作。此时进度里没有正式题面。
2. CLI 将会话、操作及控制代次交给 LangGraph 的首题节点。节点读取当下审核题库，优先计划原题。同一考察点的审核新版可用，并记录修订差异。原题下架或考察点改变时，可用同方向、同难度的剩余审核题，避开后续计划已预留的题目与重复考察点。
3. 再用一个事务保存正式题面、题库修订、出处、评分维度和要点，同时完成操作与步骤回执。此后 `state` 只读已保存的正式题。题库后续变化与旧题的回读彼此独立。

`exchange` 保存实际展示的题面。`turn` 保存题库与计划版本、出处及 rubric 快照。步骤回执和图状态保存 ID，普通进度仅展示当前正式题面。项目生成、改写、FAISS 排序与答题将在后续批次接入。

| 检查项 | 实际结果 |

## 怎样复现

首次可使用 `uv` 准备隔离环境。已装好依赖时可直接使用现有的 Python 环境。LangGraph 复用 X02 锁定版本，FAISS 依赖用于全量回归。

```powershell
uv venv --python .venv/Scripts/python.exe data/index/m2-env
$py = '.\data\index\m2-env\Scripts\python.exe'
uv pip install --python $py -r requirements-p0.lock.txt -r requirements-embed.txt -r requirements-langgraph-experiment.lock.txt
uv pip check --python $py
```

使用合成材料，按下面次序运行。材料确认时可选择知识专项，把返回的 `session_id` 填入 `$session`。计划生成后使用它返回的 `revision` 开始。

```powershell
$demo = "data/experiments/first-question-demo-$([guid]::NewGuid().ToString('N'))"
& $py -X utf8 scripts/question_bank.py --db "$demo/questions.db" import
& $py -X utf8 scripts/material_profile.py --db "$demo/interviews.db" create
$session = '<session_id>'
& $py -X utf8 scripts/interview_plan.py --db "$demo/interviews.db" --bank "$demo/questions.db" build $session --expected-revision 1 --key demo-plan
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" --bank "$demo/questions.db" start $session --expected-revision 2 --key demo-start
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session
& $py -X utf8 -m unittest discover -s tests -p 'test_first_question.py' -v
```

`start` 返回丢失时重发同一命令可查看已有操作。若 `state` 显示 `queued`，用 `scripts/interview.py resume-start <session_id> <operation_id>` 继续，并带上相同的 `--db` 和 `--bank`。重新读取正式题时无需题库查询。
