# M2 第八批 · 主动结束和部分报告

日期 2026-11-22，开发基线 `1a17052`。本批支持在计划或面试中主动结束，保留已提交的回答和已有评分。

## 主动结束怎样处理

1. `abort` 核对访问、修订和原因。一个事务内设置 `FINISHED`，增加控制代次，取消旧操作并登记独立的 `finalize`。已回答的中断题保留答复，未完成的其他计划项记为 `unanswered`。重复结束返回原结果。
2. 收尾节点复用现有的评分校验。已经出过的追问仍可在报告看到，尚未交的答复不参与评分。已有评分保留。没有可用评分样例时，中断题记录待补评原因。
3. 收尾回执与评分先提交，再单独保存部分报告。有效评分为零道时生成摘要，保留提交与原因。若报告写入失败，可以重试保存；会话在此期间已经结束。

本批验证使用合成答案和本地评分样例。正式模型、跳题与浏览器面试流程分别随后续阶段接入。

## 验收结果

| 检查项 | 实际结果 |
|---|---|
| 停止与幂等 | 零答案中止立即结束。并发同键只创建一个收尾操作，换键重试保持原原因与时间，同键改原因冲突 |
| 迟到结果 | 在追问和评分回调里触发结束，迟到的追问未发布，迟到的单题评分无法覆盖收尾结果。队列里的开始和推进也被取消 |
| 部分报告 | 合成评分保留有效 0 分；对已展示未回答的追问，只用已提交答复评分。无样例时通过 CLI 保存含已提交回答的摘要 |
| 故障与旧库 | 注入报告写入失败后，会话保持结束，恢复时复用评分。v1 材料会话可在新进程继续收尾并升级至 v5，见 [ISSUE-010](问题记录.md#issue-010--旧库主动结束后缺少收尾步骤表) |
| 自动化回归 | 9 项主动结束定向测试、全量 146 项通过 |

## 怎样复现

先按[首答保存](阶段审阅-M2首答保存.md#怎样复现)创建合成会话并保存一条回答。沿用 `$py`、`$demo`、`$session`，保持题目仍在进行中。

```powershell
$state = & $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session | ConvertFrom-Json
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" abort $session --expected-revision $state.revision --key demo-abort --reason no_time
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" report $session
& $py -X utf8 -m unittest discover -s tests -p 'test_finalization.py' -v
```

报告应给出 `end_reason=no_time`、`is_partial=true`、已答 1 和有效评分 0。收尾中断时，从 `state.operation.operation_id` 拿到 ID，执行 `resume-finalize <session_id> <operation_id>`。
