# M2 第六批 · 下一题与会话进度

日期 2026-11-21，开发基线 `a4a9208`。本批让已收尾的题目推进至下一道题，并在最后一个计划项收尾后结束会话。

## 从当前题到下一题

1. `start` 仍负责首题。用 `advance` 明确推进时，服务核对会话阶段、修订、当前题和活跃操作，登记待推进的操作。按冻结版本的计划顺序准备最早的未处理项。
2. 后续审核知识题沿用首题的发布逻辑，重新核对审核与修订，排除已发布的题 ID、规范化文本及考察点，保留后面仍待使用的计划题。待生成的项目项目前记录 `MODEL_UNAVAILABLE`。知识候选耗尽记为 `QUESTION_UNAVAILABLE`。已记录生成失败的项随同一操作继续推进。
3. 同一事务保存正式题面与评分依据、失败原因和操作回执。所有计划项都收尾时，业务库设置 `FINISHED`、`completed` 和结束时间。`state` 返回当前题号和进度，可区分已答题与有效评分题。

本批采用本地审核题和人工构造的合成评分样例。真实项目出题、个性化 FAISS 排序、跳过操作和整场报告待对应阶段接入。没有改变现有数据库迁移文件。

## 怎样复现

先按[单题评分](阶段审阅-M2单题评分.md#怎样复现)在合成会话中收尾首题。以下命令沿用 `$py`、`$demo` 和 `$session`。示例 `state` 的 `progress.closed` 为已收尾数，`current.seq` 为当前题所在的原计划位。

```powershell
$closed = & $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session | ConvertFrom-Json
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" --bank "$demo/questions.db" advance $session --expected-revision $closed.revision --key demo-advance-1
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session
& $py -X utf8 -m unittest discover -s tests -p 'test_advancement.py' -v
```

同一命令重试使用原修订与请求标识。若操作已登记仍在排队，用 `resume-advance <session_id> <operation_id>` 继续，沿用相同的 `--db` 与 `--bank`。
