# M2 第十二批 · 模型适配

日期 2026-11-22，开发基线 `817417f`。本批交付 DeepSeek 结构化请求与会话预算之间的适配。

## 请求和用量怎样处理

1. `DeepSeekGateway.invoke_json` 读取现有主模型和超时配置，要求明确的价格快照及输出上限。预算先按 UTF-8 文本字节数加包装余量估算，并保留同一次调用的最大输出额度。
2. 预留成功后封装一条非流式 Chat Completions 请求，`max_tokens` 使用预算入口传入的上限。请求输出为 JSON 对象，沿用预试测的非思考模式；HTTPS 连接使用现有超时配置，响应读取有大小上限。[DeepSeek 请求契约](https://api-docs.deepseek.com/api/create-chat-completion/)
3. 校验供应商回报的输入、输出、总量和缓存命中。先结算已知用量，再处理内容。确认了用量但 JSON 不完整、超过请求的输出额度时，内容退回，费用照记。缓存详情缺省时按未命中计算，整体用量缺失或矛盾时保留预留。
4. 配置类失败、临时 HTTP 故障和无效内容向上返回安全错误码。一次调用只发送一个请求。业务是否重试由后续接线处理。[DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)

本阶段使用本地替身核对协议并注入现有追问节点。实际供应商兼容性、真实流程效果、价格与试测额度以之后的授权试测为准。
