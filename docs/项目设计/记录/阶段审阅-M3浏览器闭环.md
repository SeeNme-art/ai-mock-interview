# M3 本地浏览器闭环验收

基线 `f7d3039`。本阶段沿用 M2 服务与 SQLite 状态，将用户入口切换到本机浏览器。

| 验收领域 | 实际验证 |
|---|---|
| 五个业务页面 | 历史、材料、规划、面试、报告，Jinja2 渲染页面壳并由原生 JS 调用本机 API |
| 完整面试 | Edge 实际打开浏览器，从内置示例开始，确认并完成 3 道知识及 2 道项目题，第一题显示示例追问 |
| 恢复与幂等 | Edge 第一题完成后刷新仍显示 1/5。HTTP 测试重复回答回执一致，模拟后台尚未处理时重启并继续 |
| 历史与导出 | Edge 打开报告并核对五道题，独立读取 Markdown 下载响应；通过历史再练一次得到新会话。接口验证分页、报告门禁和导出文字转义 |
| 删除 | Edge 从历史发起删除。HTTP 验证活跃禁止删除、注入失败后正文不可读、备份与该场 trace 清理、重启重试和重复删除 |
| 页面检查 | Edge 390 px 下检查报告页无水平溢出，桌面实测无 JS 未捕获错误 |
| 回归 | Web 接口 5 项、全量 191 项通过，真实模型调用 0 次 |

本阶段浏览器模式保持在本机。示例用固定评分验证流程，粘贴文本用标签提取和手工确认，个人材料的问答可复盘，评分等待真实模型接线和授权试测。文件输入、题库扩大及质量校准留给后续阶段。删除覆盖现有业务库、应用迁移备份和观测库。当前面试流程通过业务库回执恢复，正式图 checkpoint 仍待接入。

## 怎样复现

```powershell
py -3.12 -m venv .venv
$py = '.\.venv\Scripts\python.exe'
& $py -m pip install -r requirements-p0.lock.txt -r requirements-langgraph-experiment.lock.txt -r requirements-web.txt
$env:PYTHONPATH = 'src'
& $py -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

打开 [本机面试工作台](http://127.0.0.1:8000/)，依次选择「使用示例」「预览材料」「确认材料，进入规划」「生成计划」和「开始面试」。首题完成后刷新一次，再完成剩余题目。报告可以下载 Markdown，随后可从历史再练和删除。

需要验证个人材料时可粘贴带 `岗位描述：`、`技能：`、`项目做法：` 与 `项目结果：` 的合成文本。材料确认前可修改结构化字段。另在终端运行 `& $py -X utf8 -m unittest discover -s tests -p 'test_web_interview.py' -v` 可复现 HTTP 与故障分支。[FastAPI 模板文档](https://fastapi.tiangolo.com/advanced/templates/)
