# M1 第三批 · 纯文本材料与人工确认画像

日期 2026-11-21，开发基线 `b90b997`。本批验收本地材料入口、人工编辑、确认与重新读取，作者已回复“审阅通过”。

## 一次确认怎样写入

1. 用户可打开 UTF-8 文本预览，或者直接填写技能、JD 与项目字段。预览会遮盖常见联系方式。课程作业只需填写“做了什么”，项目名、背景和结果可以留空。
2. CLI 在当前进程内保存一份草稿，用户可重新填写再确认。30 分钟后拒绝确认未使用的草稿。项目字段区分 `provided`、`edited` 与 `missing`，无项目时须主动选择知识专项。
3. 确认后向独立的业务 SQLite 库写入一条 `PLANNING` 会话。长期记录只保存已确认画像与 JD 等会话字段。命令返回会话 ID，下一进程可以读取。材料更新时，新草稿会创建新会话。

同一个确认请求重试时，先在事务中查已有结果，再检查草稿是否过期。这样，即使数据库写成功后响应丢失，调用方重发相同请求仍可拿到同一会话 ID。并发由 SQLite 写事务与唯一约束兜住。CLI 每次交互生成新的请求标识，跨草稿过期或重启的重复确认行为在服务层验证。

## 验收结果与边界

| 检查项 | 实际结果 |
|---|---|
| 预览、修改和重新读取 | 两个独立 CLI 进程实测；数据库保存修改后的字段与来源，原文和初稿合成标记未写入 |
| 没有项目 | 明确选择知识专项才可确认 |
| 重复、并发或过期 | 同键同内容复用，同键改内容及同草稿换键均拒绝；两次并发同键只有一行；无有效草稿不创建会话 |
| 数据库版本 | 初次迁移和确认同事务，未知库和被改动的校验值会被拒绝；公共题库回归通过 |
| 隐私边界 | 合成邮箱、身份证和全角手机号有规则测试。常见模式之外需人工检查。材料处理无网络请求 |
| 全量回归 | 46 项测试通过，其中新增 8 项材料测试 |

本批沿用 SQLite 与现有依赖。文本预览的上限是 16,000 字符，另有 JD、项目与技能字段上限。这些是本地 CLI 的初始限制，正式入口随样本回归调整。CLI 重填时按原项目顺序修改，草稿过期在确认时检查。Web 的后台缓存清理、WAL 并发配置、模型抽取、PDF/DOCX 与会话规划仍待对应阶段。

## 怎样复现

在仓库根目录运行。先用合成材料，项目描述可填写“为课程检索练习实现分块”，其他项目字段可以留空。需要试验纯文本预览时，将自己准备的合成 UTF-8 文件通过 `create --text-file` 指定。`q` 取消，`e` 重新填写。确认后复制输出的 `session_id` 用于读取。

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -X utf8 scripts/material_profile.py --db data/experiments/materials-demo.db create
& $py -X utf8 scripts/material_profile.py --db data/experiments/materials-demo.db show '<session_id>'
& $py -X utf8 -m unittest discover -s tests -p 'test_materials.py' -v
```

默认业务库在 `data/interviews.db`。示例单独指定演示数据库。数据库及写入期间使用的 SQLite 日志文件均已加入 Git 忽略规则。
