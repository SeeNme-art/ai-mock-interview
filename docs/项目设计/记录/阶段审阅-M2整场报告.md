# M2 第七批 · 整场模板报告

日期 2026-11-22，开发基线 `ce5ed72`。本批让已结束的面试能够生成、保存和重新查看一份带证据的整场报告。

## 数据怎么流动

1. `generate-report` 确认可访问的会话已经结束。按冻结计划顺序读取每项的实际题面、已提交答案、评分与来源，从原来保存的评分维度和证据复用评分核验与聚合。
2. 知识和项目分别计算均分，并附有效题数与维度样本数。有答案但评分失败计入已答和系统失败。没能出题的计划项计入系统失败。真实零分参与均分；缺少有效分的类别为 `null`。没有有效分时返回会话摘要。
3. 对有已验证回答引用且低于 3 分的维度，优先选分数较低的项，同一维度提一次，最多三项。每项给出题号、引用、练习动作和自查方法，可用引用位置回到答案。
4. 快照与统计写进 `report_revision`，初版编号为 1。并发生成复用成功保存的同一份报告，查看时无需题库和模型。旧库按编号升级、保留备份。报告写入故障时，面试仍已结束，可重新生成。

本批的报告是结构化 JSON 模板，项目分类用合成已存评分验证。本批支持读取已有修订；主动结束、模型报告叙述、补评新增修订及 Markdown 导出随对应阶段接入。

## 怎样复现

沿用[会话推进](阶段审阅-M2会话推进.md#怎样复现)的 `$py`、`$demo` 和 `$session`。完成最后一个计划项后，先确认 `state.phase` 为 `FINISHED`。用相同会话 ID 先生成，再读指定修订。

```powershell
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" generate-report $session
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" report $session --revision 1
& $py -X utf8 -m unittest discover -s tests -p 'test_reports.py' -v
```

生成初版前用 `report $session` 可查询是否待生成。复现使用本地合成会话和被忽略的运行数据库。
