## 2. ISSUE-001 · 关闭完整 IO 存储仍会保存正文预览

- 发现日期：2026-11-17。
- 类型：实现与新设计差异 / 数据最小化。
- 发现方式：整理新交接时静态核查，未声称发生真实资料泄露事故。
- 预期：D18 已确认默认不在日志/trace 保存简历、回答或完整 Prompt 的正文片段。
- 实际代码：`config.py` 默认 `observe_store_io=False`，但 `observe_io_preview_chars=120`；`store._dump()` 的 full=False 分支仍取 `text[:preview]`；写入 span 时对 input/output 调用该函数。

### 排查与证据

执行只读查找：

```powershell
rg -n 'observe_io_preview_chars|def _dump|return head|_dump\(s.input|_dump\(s.output' src/app/config.py src/app/observability/store.py
```

定位：[config.py](../../../src/app/config.py) 第 43 行默认预览长度；[store.py](../../../src/app/observability/store.py) 的 `_dump` 与 `_write`。调用链说明只关闭 full 模式不会禁止正文落入数据库。

### 根因与影响

旧设计的目标是限制体积，所以保留截断预览；新版已选择更严格的数据最小化。截断只缩短文本，不能保证去掉个人信息。业务如果传入真实正文，该路径会保存其中一部分。

### 处理计划（尚未实施）

- 默认 metadata-only；调用边界不向普通 trace 提交正文，存储层再次防止旁路写入。
- 如保留正文调试，只允许显式开启且使用合成样本，明确生命周期。
- 不能仅将 preview 设为 0 就认为完成：当前函数可能仍输出省略号，且完整模式、异常和 callback 路径需一起检查。
- 用合成标记串贯通 trace、日志、异常、checkpoint，默认模式扫描不得出现该标记；同时验证节点/时长/错误码仍可诊断。

### 验证与可讲述边界

当前状态：静态差异已确认，代码未修改，运行验证未执行。现在只能讲“设计整合时发现了旧预览机制与数据最小化的冲突”；修复并验证后才能讲“我实现并验证了默认不记录正文”。
