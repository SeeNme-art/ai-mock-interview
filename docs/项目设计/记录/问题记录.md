## 2. ISSUE-001 · 关闭完整 IO 存储仍会保存正文预览

- 发现日期：2026-11-17。
- 类型：实现与新设计差异 / 数据最小化。
- 发现方式：整理新交接时静态核查，未声称发生真实资料泄露事故。
- 预期：D18 已确认默认不在日志/trace 保存简历、回答或完整 Prompt 的正文片段。
- 实际代码：`config.py` 默认 `observe_store_io=False`，但 `observe_io_preview_chars=120`；`store._dump()` 的 full=False 分支仍取 `text[:preview]`；写入 span 时对 input/output 调用该函数。

### 排查与证据

执行只读查找：

```powershell
rg -n 'observe_io_preview_chars|def _dump|return head|_dump\(s.input|_dump\(s.output' src/app/config.py src/app/observability/store.py
```

定位：[config.py](../../../src/app/config.py) 第 43 行默认预览长度；[store.py](../../../src/app/observability/store.py) 的 `_dump` 与 `_write`。调用链说明只关闭 full 模式不会禁止正文落入数据库。

### 根因与影响

旧设计的目标是限制体积，所以保留截断预览；新版已选择更严格的数据最小化。截断只缩短文本，不能保证去掉个人信息。业务如果传入真实正文，该路径会保存其中一部分。

### 当时的处理计划

- 默认 metadata-only；调用边界不向普通 trace 提交正文，存储层再次防止旁路写入。
- 如保留正文调试，只允许显式开启且使用合成样本，明确生命周期。
- 不能仅将 preview 设为 0 就认为完成：当前函数可能仍输出省略号，且完整模式、异常和 callback 路径需一起检查。
- 用合成标记串贯通 trace、日志、异常、checkpoint，默认模式扫描不得出现该标记；同时验证节点/时长/错误码仍可诊断。

### 验证与可讲述边界

2026-11-19 已修改当前路径：trace 边界不再提交 input/output；存储入队与写入均不序列化正文；异常转为安全代码；日志字段白名单过滤嵌套内容，formatter 不写原始消息与 traceback。P0 不提供正文调试开关，旧完整模式明确拒绝启动。

验证见 `tests/test_p0.py`：合成标记串经过 input/output、嵌套日志和异常，SQLite dump、文件日志与控制台均不含标记；原异常仍由业务捕获，trace 状态、总 token 和安全错误码保留。绕过 tracing 直接写 store 也不保存正文。原演示脚本在独立临时目录产生 3 条 trace / 11 条 span。

历史库原有正文读取时被隐藏，数据库字节未自动擦除，测试明确检查了这一区别。本次没有接入 LangGraph/checkpoint 或真实模型 callback，不能宣称这些未来路径已经通过隐私验证；事件名、节点名和白名单标签仍要求调用者只传代码定义的元数据。

当前可讲“完成并用合成回归验证 P0 默认不记录正文”；不能讲成发生过生产泄露或覆盖了尚未开发的全部业务。

## ISSUE-002 · SQLite 上下文只处理事务，连接仍占用文件

- 日期：2026-11-19，P0 工程核验。
- 现象：首轮 11 项 unittest 中，4 项断言完成后在 tearDown 清理临时目录时触发 WinError 32，提示 observe.db 被占用；HTTP 和正文隔离检查通过。
- 定位：测试中 `with sqlite3.connect(...) as conn` 只完成事务提交/回滚，不负责连接 close；对照检查发现原 store 短读取也有相同用法。不能归因于“WAL 文件存在，所以 SQLite 有 bug”。
- 修复：store 的初始化和短读取用 `contextlib.closing` 管理连接；测试连接也显式关闭，写入场景显式 commit。后台写线程的连接由线程 finally 关闭。
- 验证：修正测试连接后，同组 11 项通过；随后加入演示脚本回归，最终结果在 P0 阶段审阅单登记。没有用强删文件或忽略清理异常掩盖失败。
- 可讲述边界：这是本地测试发现的资源生命周期问题；不是线上故障，也不是业务会话删除功能已经完成。
