# M2 第九批 · 跳过当前题

日期 2026-11-22，开发基线 `5700f2e`。本批让用户跳过整道当前题，并按原计划继续面试。

## 跳过以后发生什么

1. 核对当前会话、题目 ID 和版本。先识别同键重试，避免把它作用到后续题。
2. 一个事务内登记跳过、保留已发布问答、取消旧操作、清理无结果的待评分占位，并登记待推进操作。控制代次更新后，迟到的追问与评分无法写回。
3. 复用原有推进节点准备下一题，顺序保持在冻结计划内。下一题暂不可用时保留原因。最后一题跳过后按正常结场处理，报告单独生成。
4. 有已交答案的跳过题计入已答和跳过。报告保留问答，跳过题不计分，也不记系统失败。

## 验收结果

| 检查项 | 实际结果 |
|---|---|
| 顺序与并发 | 两个命令行进程重复同一次跳题，只创建一条操作并发布下一道题。旧修订、已结束的题和同键改目标均被拒绝 |
| 迟到结果 | 跳题发生在追问或评分返回前，旧结果无法写回，已提交答案仍在。跳首题后继续剩余四题，报告已答 5、有效评分 4、跳过 1，合成知识均分 75.0 |
| 正常结场与缺题 | 跳过末题后面试正常结场，保留之前四题分数。混合计划未能生成的项目题保留原因，不计入用户跳过数 |
| 事务与恢复 | 注入跳题登记失败时，题面状态、评分占位和原操作一起回滚。已登记跳题但下一题准备失败时，新命令行进程可继续同一个操作 |
| 自动化回归 | 新增 7 项，18 项推进定向、全量 153 项通过。验证使用合成答复和评分样例 |

## 怎样复现

按[首答保存](阶段审阅-M2首答保存.md#怎样复现)启动合成会话并交一条答复，沿用 `$py`、`$demo`、`$session`。保持当前题尚未完成评分。

```powershell
$state = & $py -X utf8 scripts/interview.py --db "$demo/interviews.db" state $session | ConvertFrom-Json
$skip = @('skip', $session, $state.current.turn_id,
          '--expected-revision', $state.revision, '--key', 'demo-skip')
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" --bank "$demo/questions.db" @skip
& $py -X utf8 scripts/interview.py --db "$demo/interviews.db" --bank "$demo/questions.db" @skip
& $py -X utf8 -m unittest discover -s tests -p 'test_advancement.py' -v
```

已答和跳过都为 1、有效评分为 0。下一个可用计划位显示在 `current.seq`。若回执显示排队，使用相同业务库和题库执行 `resume-skip <session_id> <operation_id>`。
