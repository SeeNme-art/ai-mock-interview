# M2 命令行闭环验收

日期 2026-11-22。作者授权 M2 内逐批自审、修复、提交和推送。M2 收尾后停止，M3 恢复作者审阅。

## 本批业务范围

- 混合面试按冻结计划交替推进知识与项目题。项目模板仅使用确认后的实施或结果字段，保存对应项目、字段和引用，冻结项目评分维度。
- 追问与评分可使用预算网关。合成验证覆盖两轮追问上限、暂时错误的最多两次尝试、未知用量预留以及评分预算不足收尾。
- 首题、跳题、主动结束、恢复和报告继续使用既有业务状态与回执。评分仍需校验适用维度与原答复证据。

## 验收记录

| 场景 | 实际结果 |
|---|---|
| 知识专项 | 5 题均展示并保存有效评分，知识有效题数 5，项目分为空。首题两轮追问，合成传输 11 次 |
| 混合面试 | 3 道知识与 2 道项目均保存分项评估。项目题原文引用可回到确认的字段，首题两轮追问，合成传输 11 次 |
| 评分预算不足 | 结束原因 `budget_exhausted`，保留 1 道已答，实际发送 0 次，报告为无分摘要 |
| 供应商故障 | 5 道已答，追问和评分各步骤至多两次，共 20 次合成尝试，保留未知用量并输出无分摘要 |
| 向量规划 | 独立 CLI 使用本机 BGE 与 FAISS，三个方向均返回排序元数据，生成 5 道计划题；缺模型时按审核库回退 |
| 跳题、中止与恢复 | 已有专项覆盖重放防重、最后一题跳过、同键中止、答案和评分迟到、跨进程恢复与报告写入故障 |
| 最终回归 | 规划 17 项、离线演示专项 3 项、全量 186 项通过。未发起真实供应商调用 |

报告分数、供应商响应和报价均为合成示例。真实模型效果、正式每题和全局预算配置、运行时图 checkpoint 及 Web 交互仍按后续工作跟踪。

## 怎样复现

```powershell
$py = '.\data\index\m2-env\Scripts\python.exe'
& $py -X utf8 scripts/m2_demo.py
& $py -X utf8 -m unittest discover -s tests -q
```

演示在临时库中走四种场景，支持 `--case mixed` 只运行混合面试。向量规划复用已准备的模型及索引，另见 [M1 向量检索](阶段审阅-M1向量检索.md#怎样复现) 与项目首页的规划参数。
